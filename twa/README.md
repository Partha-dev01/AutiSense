# AutiSense TWA (Trusted Web Activity) Android Build

This folder wraps the live AutiSense PWA (`https://autisense.imaginaerium.in`) as a
native Android app using a **Trusted Web Activity** generated by
[Bubblewrap](https://github.com/GoogleChromeLabs/bubblewrap).

A TWA is a thin Android shell that renders the PWA full-screen with **no browser URL
bar** — *provided* Digital Asset Links verification passes (see below). If verification
fails, Android falls back to a Custom Tab and the URL bar is shown.

- Android package id: `in.imaginaerium.autisense`
- App version: name `1.0.0`, code `1`
- TWA manifest: [`twa-manifest.json`](./twa-manifest.json)
- Asset links served at: `https://autisense.imaginaerium.in/.well-known/assetlinks.json`
  (source: [`../public/.well-known/assetlinks.json`](../public/.well-known/assetlinks.json))

---

## Prerequisites

| Tool | Version | Notes |
|------|---------|-------|
| Node.js | 18 LTS or newer | Bubblewrap CLI runtime |
| JDK | **17** | Required by the current Android Gradle plugin |
| Android SDK + build-tools | latest | `ANDROID_HOME` / `ANDROID_SDK_ROOT` must be set |
| `@bubblewrap/cli` | latest | `npm i -g @bubblewrap/cli` (or `npx @bubblewrap/cli`) |

On first run, Bubblewrap can install a managed JDK + Android SDK for you
(`bubblewrap doctor` checks the environment). CI uses pinned, pre-installed versions.

## One-time keystore generation (USER TASK)

The release signing keystore is **not** in this repo. Generate it once and keep it
secret (back it up — losing it means you can never update the Play listing).

```bash
keytool -genkeypair \
  -v \
  -keystore android.keystore \
  -alias autisense \
  -keyalg RSA \
  -keysize 2048 \
  -validity 10000 \
  -storetype PKCS12
```

- Place the resulting `android.keystore` at the **repo `AutiSense/` root** (one level up
  from this folder), so it matches `signingKey.path` (`../android.keystore`) in
  `twa-manifest.json`. In CI the keystore is restored to that path from a secret.
- Use the alias `autisense` (matches `signingKey.alias`).

## Get the SHA-256 fingerprint and wire up asset links

The TWA only drops the URL bar when the app's signing certificate fingerprint is listed
in the live `assetlinks.json`.

1. Print the fingerprint of the release keystore:

   ```bash
   keytool -list -v -keystore android.keystore -alias autisense
   ```

   Copy the `SHA256:` line value, e.g. `AB:CD:EF:...:99` (colon-separated hex).

2. Edit [`../public/.well-known/assetlinks.json`](../public/.well-known/assetlinks.json)
   and replace the placeholder

   ```
   REPLACE_WITH_SHA256_FINGERPRINT_OF_RELEASE_KEYSTORE
   ```

   with that exact fingerprint string.

3. Deploy so it is served (with `Content-Type: application/json`) at:

   ```
   https://autisense.imaginaerium.in/.well-known/assetlinks.json
   ```

> ⚠️ Without a matching `assetlinks.json` fingerprint, the installed TWA will show a
> **browser URL bar** at the top (Custom Tabs fallback) instead of running full-screen.
> The fingerprint must match the certificate that actually signs the APK/AAB.

You can validate the pairing with Google's
[Statement List Generator and Tester](https://developers.google.com/digital-asset-links/tools/generator).

## Build the app

From this `twa/` folder (where `twa-manifest.json` lives):

```bash
# Generate the Android project from the manifest (first time only)
bubblewrap init --manifest=./twa-manifest.json

# Build the signed APK + AAB (non-interactive once keystore + manifest are in place)
bubblewrap build
```

Outputs:

- `app-release-signed.apk` — sideload / direct install / testing
- `app-release-bundle.aab` — upload to Google Play

Re-running `bubblewrap build` after editing `twa-manifest.json` regenerates and rebuilds.
Bump `appVersionCode` (and usually `appVersionName` / `appVersion`) for every Play update.

---

## CI

The Android app is built in CI via **GitHub Actions** (repo `Partha-dev01/AutiSense`).
The workflow installs JDK 17 + the Android SDK + `@bubblewrap/cli`, restores the keystore
secret to `AutiSense/android.keystore`, and runs `bubblewrap build` against
`twa/twa-manifest.json`. Do not commit the keystore or its passwords.
